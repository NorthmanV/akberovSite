# Проект: Сайт-портфолио iOS-разработчика

Создаём веб-сайт для портфолио iOS-разработчика.

## Общие правила

- Перед тем как вставлять новый код, проверь, чтобы он ничего не ломал, не нарушал текущую структуру и не конфликтовал с уже существующим кодом.
- Сначала продумай пошагово — опиши план того, что нужно построить, в виде подробного псевдокода. Подтверди план, затем пиши код.
- Всегда пиши корректный код, соответствующий лучшим практикам, принципу DRY (не повторяйся), без багов, полностью рабочий.
- Приоритет — читаемость кода, а не производительность.
- Полностью реализуй всю запрошенную функциональность. Никаких TODO, заглушек или недостающих частей.
- Убедись, что код полный и тщательно проверен. Включай все необходимые импорты и правильно именуй ключевые компоненты.
- Будь кратким. Минимум лишнего текста.
- Если считаешь, что правильного ответа может не быть — скажи об этом. Если не знаешь ответа — скажи, а не угадывай.

## Технологический стек

- ReactJS / NextJS
- JavaScript / TypeScript
- TailwindCSS
- HTML / CSS

## Рекомендации по написанию кода

- Используй ранние возвраты (early returns) для повышения читаемости кода.
- Всегда используй классы Tailwind для стилизации HTML-элементов; избегай CSS или тегов `<style>`.
- Используй `class:` вместо тернарного оператора в атрибутах классов, где это возможно.
- Используй описательные имена переменных и функций/констант. Функции-обработчики событий должны начинаться с префикса «handle» (например, `handleClick` для onClick, `handleKeyDown` для onKeyDown).
- Реализуй функции доступности (accessibility) для элементов (например, `tabindex="0"`, `aria-label`, `onClick`, `onKeyDown`).
- Используй стрелочные функции через `const` вместо объявлений `function` (например, `const toggle = () =>`). По возможности определяй тип.
